# Interface specifications

Version 1 of every format. All examples are in [`examples/`](../examples) and are regenerated by `./gradlew :bench:run`.

## 1. Java API

| Call | Purpose |
|---|---|
| `Gateway.withDefaults()` | Built-in definitions, all four codecs, standard redundancy policy |
| `encode(Message, format)` / `decode(byte[], format)` | Format ids: `cot`, `xml`, `slash`, `bin` |
| `transcode(byte[], from, to)` | Convert between any two formats |
| `prepare(Message, LinkProfile)` | Encode in the link's preferred format, fragment, and add RS parity |
| `Fragmenter.Reassembler.accept(byte[])` | Returns the payload once enough fragments have arrived |
| `XsdGenerator.generate(defs)` | W3C XML Schema for the `xml` format |
| `DefinitionRegistry.register(MessageDef)` | Add a message type at run time |
| `CodecRegistry.register(Codec)` | Add a wire format |

Every decoder validates its input fully, and malformed input raises `ValidationException`. XML parsing rejects DOCTYPE declarations and external entities.

## 2. Message definition (JSON)

```json
{
  "id": "MEDEVAC9", "version": 1, "code": 1,
  "title": "...", "xmlName": "MedicalEvacuationRequest",
  "cotType": "b-r-f-h-c", "pointField": "pickupLocation",
  "defaultPrecedence": "IMMEDIATE",
  "fields": [
    { "name": "pickupSecurity", "set": "L6", "xml": "PickupSiteSecurityCode",
      "type": "ENUM", "required": true, "label": "...",
      "codes": [ {"code": "N", "label": "No enemy troops in area"}, ... ] }
  ]
}
```

| Type | Canonical value | Limits |
|---|---|---|
| `POSITION` | lat/lon in 1e-5 degrees (about 1.1 m) | – |
| `TEXT` | upper-case, ASCII 0x20–0x5F except `/` (the DEC SIXBIT set, ADatP-3 convention) | `max` length |
| `INT` | integer | `min`, `max` |
| `DECIMAL` | exact decimal | `min`, `max`, `scale` |
| `ENUM` | one code | `codes` |
| `ENUM_SET` | zero or more codes (must be alone in its set) | `codes` |
| `COUNTS` | count per code; zeros omitted (must be alone in its set) | `codes`, `max` per code |
| `DTG` | UTC, one-minute resolution, 2020–2051 | – |

## 3. Message header (all formats)

| Element | Description |
|---|---|
| definition id and version | identify the message type |
| originator | call sign, up to 12 characters |
| serial | 0–65535 |
| time | UTC, minute resolution |
| precedence | `ROUTINE`, `PRIORITY`, `IMMEDIATE` or `FLASH` |

## 4. Cursor-on-Target (`cot`)

This is a standard CoT 2.0 `event`. The definition's `pointField` becomes `<point>`. The report travels in a `<tng_msg>` detail element:

```xml
<tng_msg def="MEDEVAC9" ver="1" orig="BRAVO22" serial="42" prec="IMMEDIATE">
  <f n="patientsByPrecedence" v="A2 C1"/> ...
</tng_msg>
<remarks>9-Line MEDEVAC Request ... (plain-language summary)</remarks>
```

TAK clients that don't have the plugin still display the marker and the plain-language `remarks`.

## 5. Structured XML exchange (`xml`)

- Namespace `urn:truenorthtak:gateway:exchange:1`, prefix `tng`.
- Elements are qualified and named in NIEM style with representation terms (`...Code`, `...Text`, `...Value`, `...DateTime`).
- The schema is [`schema/gateway-exchange-1.xsd`](../schema/gateway-exchange-1.xsd), generated from the definitions.
- `ENUM_SET` fields are repeated elements. `COUNTS` fields are repeated `{CategoryCode, Quantity}` pairs.

This is a representative exchange model. Mapping to an authoritative model (for example NIEM 6 or MTF-XML) is planned as an additional codec.

## 6. Character-oriented text (`slash`)

This is a representative grammar in the ADatP-3 style, encoded in 7-bit ASCII.

```
message   = msgid-set dtg-set { field-set }
msgid-set = "MSGID/" def-id "/" version "/" originator "/" serial "/" precedence "//" EOL
dtg-set   = "DTG/" dtg "//" EOL
field-set = set-id { "/" field } "//" EOL
dtg       = DD HH MM "Z" MON YY                 ; e.g. 101845ZOCT26
position  = DD.DDDDD ("N"|"S") "/" DDD.DDDDD ("E"|"W")
count     = code digits                          ; e.g. A2
field     = "-"  (no value) | value
```

- Fields that share a `set` id are written in one set, in definition order.
- `ENUM_SET` and `COUNTS` fields list one code (or code plus count) per field.
- A set whose fields are all absent is omitted.
- Line breaks are optional when parsing.

## 7. Compact binary (`bin`)

The format is bit-packed MSB-first and padded with zeros to a whole byte.

| Item | Bits |
|---|---|
| definition code | 8 |
| definition version | 4 |
| precedence | 2 |
| originator length, then 6-bit characters | 4 + 6 × length |
| serial | 16 |
| time (minutes since 2020-01-01T00:00Z) | 24 |
| presence flags: 1 per optional field, in definition order | n |
| fields present, in definition order | see below |

| Type | Encoding |
|---|---|
| `POSITION` | lat + 9,000,000 (25 bits), lon + 18,000,000 (26 bits) |
| `TEXT` | length in ⌈log2(max+1)⌉ bits, then 6 bits per character (char − 32) |
| `INT` | value − min in ⌈log2(max−min+1)⌉ bits |
| `DECIMAL` | (unscaled − min × 10^scale) in the bits needed for the range |
| `ENUM` | code index in ⌈log2(codes)⌉ bits |
| `ENUM_SET` | 1 bit per code |
| `COUNTS` | ⌈log2(max+1)⌉ bits per code |
| `DTG` | 24 bits, minutes since 2020 |

## 8. Fragment and FEC framing

Every fragment begins with a 7-byte header, followed by one shard:

| Bytes | Field |
|---|---|
| 0–1 | message tag (currently the serial) |
| 2 | *k*, the number of data shards |
| 3 | *m*, the number of parity shards |
| 4 | shard index (0…k+m−1) |
| 5–6 | original payload length |

- The coding is systematic Reed-Solomon over GF(2^8) with the primitive polynomial 0x11D. The encoding matrix is a Vandermonde matrix normalised so that its top *k* rows are the identity.
- **Any *k* of the *k+m* fragments rebuild the payload.** Receivers never need to transmit.
- The default parity ratios are ROUTINE 25%, PRIORITY 50%, IMMEDIATE 100% and FLASH 150%, with at least one parity shard.
